# NEXUS Phase 1: Learned Bioelectric Prediction — PRD

## 1. Overview

NEXUS Phase 1 is a proof-of-concept system that trains a learned model to predict bioelectric state (membrane potential, Vmem) from biophysical specification (ion channel expression + gap junction topology) in non-neural tissue. The model is trained on synthetic data generated by the BETSE physics simulator and validated against published experimental Vmem measurements in Xenopus laevis embryonic ectoderm and planarian body wall epithelium.

Phase 1 answers one question: can a learned model predict bioelectric state from biophysical specification, generalize to unseen configurations, and run faster than the physics solver?

This is not on the direct path to the brain. It exists because there is no cellular-resolution Vmem ground truth for mammalian cortex. Phase 1 establishes that the prediction approach works before Phase 2 applies it to neural tissue.

### Context

NEXUS is a five-phase research program to predict the human brain's computational behavior from its molecular specification. Phase 1 is the foundation: if a learned model cannot beat a physics simulator on non-neural tissue with known ground truth, the rest of the program has no basis. Phase 1's model weights also transfer as pretrained representations for Phase 2 (transcriptome-to-electrophysiology in mouse cortex).

---

## 2. Success Criteria

The system is complete when all three criteria are met:

| Criterion | Target | How Measured |
|---|---|---|
| **Accuracy** | MAE ≤ 10% of experimental Vmem range | Predicted Vmem vs. experimental measurements from published voltage reporter dye data |
| **Generalization** | Model trained on normal-development configurations predicts perturbation conditions it has never seen | Accuracy on held-out perturbation test set (channel blockade, gap junction blockade, exogenous channel expression) |
| **Speed** | Inference time < BETSE simulation time on equivalent hardware | Wall-clock comparison on identical tissue configurations, same machine |

The 10% accuracy threshold matches BETSE's own validated accuracy against experimental data (Pietak and Levin, 2016).

Three subsystems:

1. **Data Engine**: generates synthetic training data via BETSE, curates published experimental data, and builds PyTorch Geometric datasets.
2. **Model**: a message-passing graph neural network (MPNN) that takes per-cell ion channel features and gap junction graph topology as input and predicts per-cell Vmem.
3. **Evaluator**: computes accuracy, generalization, and speed metrics against both BETSE outputs and experimental ground truth.

## 4. Data Pipeline

### 4.1 Synthetic Training Data (BETSE)

BETSE (BioElectric Tissue Simulation Engine) is the physics simulator. It solves coupled PDEs for ion transport, gap junction current flow, and membrane potential across a 2D tissue grid using finite volume methods. It is open-source, Python-based, and parameterizable via YAML configuration files.

**Repository**: https://github.com/betsee/betse

**Installation**: `pip install betse` (Python 3.8+; verify compatibility and pin version at build time).

#### 4.1.1 Parameter Space

Each BETSE simulation is defined by a configuration specifying tissue geometry, ion channel densities, and gap junction properties. The training data is generated by sampling configurations from a defined parameter space.

**Tissue geometry parameters:**

| Parameter | Range | Units | Sampling |
|---|---|---|---|
| Cell count | 50–500 | cells | Log-uniform |
| Cell radius | 5–15 | μm | Uniform |
| Tissue shape | hexagonal grid | — | Fixed for v1 |
| Simulation duration | 10–60 | seconds | Uniform |
| Time step | 0.1–1.0 | ms | Adaptive (BETSE default) |

**Ion channel density parameters (per cell):**

Each cell has densities for the following channel/transporter types. Densities are sampled independently per channel type, then assigned to cells (uniform across tissue for baseline configs, spatially varying for advanced configs).

| Channel / Transporter | Parameter name in BETSE | Density range | Units |
|---|---|---|---|
| Voltage-gated Na+ (Nav) | `Na_mem` | 0–50 | μA/cm² (max conductance proxy) |
| Inward-rectifier K+ (Kir) | `K_ir` | 0–30 | μA/cm² |
| K+ leak | `K_leak` | 0–20 | μA/cm² |
| Voltage-gated Ca2+ | `Ca_mem` | 0–10 | μA/cm² |
| Cl- channel | `Cl_mem` | 0–15 | μA/cm² |
| Na+/K+-ATPase | `NaKATP` | 0–30 | μA/cm² |
| H+/K+-ATPase | `HKATP` | 0–10 | μA/cm² |
| V-ATPase (H+ pump) | `VATP` | 0–10 | μA/cm² |

> **Note**: Exact BETSE parameter names and value ranges must be verified against BETSE's actual config schema at build time. The ranges above are approximate starting points derived from the BETSE documentation and Pietak & Levin 2016/2017. The builder should inspect `betse/science/config/` source and the example YAML configs shipped with BETSE to get the canonical parameter names and physically realistic ranges.

**Gap junction parameters:**

| Parameter | Range | Units |
|---|---|---|
| Gap junction conductance (global) | 0–50 | nS |
| Gap junction connectivity | full nearest-neighbor, random dropout (0–50% edges removed) | — |

**Perturbation conditions (held out for generalization testing):**

These are NOT included in the training set. They form the out-of-distribution test set.

| Perturbation type | Implementation |
|---|---|
| Single channel blockade | Set one channel density to 0 across all cells |
| Gap junction blockade | Set GJ conductance to 0 (or ≤5% of baseline) |
| Exogenous channel expression | Set one channel density to 3x–5x the training range max in a subset of cells |
| Spatial gradient | Linear gradient of one channel density across the tissue (not present in training) |

#### 4.1.2 Data Generation Protocol

1. **Sample N=10,000 baseline configurations** from the parameter space using Latin Hypercube Sampling (LHS) to ensure coverage.
2. **Run BETSE** for each configuration. Extract steady-state Vmem per cell (final time point after the simulation has converged). Also extract the full Vmem time series for a subset (N=1,000) for future temporal prediction work.
3. **Sample N=2,000 perturbation configurations** (500 per perturbation type) with the same base parameter ranges but with the perturbation applied.
4. **Store** each simulation result as a record:

```python
{
    "config_id": str,              # unique ID
    "tissue_geometry": {
        "n_cells": int,
        "cell_radius": float,
        "cell_positions": np.ndarray,  # (n_cells, 2) — x,y coordinates
    },
    "channel_densities": np.ndarray,   # (n_cells, n_channels) — density per cell per channel
    "gap_junctions": {
        "edge_index": np.ndarray,      # (2, n_edges) — COO format
        "conductances": np.ndarray,    # (n_edges,) — conductance per edge
    },
    "vmem_steady_state": np.ndarray,   # (n_cells,) — mV
    "vmem_timeseries": np.ndarray | None,  # (n_timesteps, n_cells) — mV, if captured
    "is_perturbation": bool,
    "perturbation_type": str | None,
    "metadata": {
        "betse_version": str,
        "sim_duration_s": float,
        "wall_clock_s": float,         # for speed benchmarking
    }
}
```

5. **Persist** as a directory of `.npz` files (one per simulation) with a manifest CSV.

#### 4.1.3 Parallelization

BETSE simulations are embarrassingly parallel. Use `multiprocessing` or `joblib` to run simulations across available CPU cores. Each simulation is independent. Target throughput: at minimum, saturate all available cores. Log estimated total generation time after the first 10 simulations complete.

#### 4.1.4 Data Validation

After generation, run automated checks:
- No NaN or Inf values in Vmem outputs.
- Vmem values within physically plausible range (−120 mV to +60 mV for all cell types).
- Steady-state convergence check: Vmem change between final two time points < 0.1 mV for ≥95% of cells.
- At least 95% of sampled configs produce valid simulations (BETSE can fail on extreme parameter combinations; log and skip failures).

### 4.2 Experimental Validation Data

Published experimental Vmem measurements serve as the ground truth for final evaluation. These are curated manually from the literature.

**Primary sources:**

| Source | System | Data type | Reference |
|---|---|---|---|
| Pai et al. 2018 | Xenopus laevis embryo | Vmem maps from voltage reporter dyes (CC2-DMPE + DiBAC4(3)), normal and HCN2-injected | Nature Communications 9:998 |
| Adams & Levin 2012 | Xenopus laevis embryo | Vmem patterns during craniofacial development | Developmental Dynamics 241(12):1794–1817 |
| Beane et al. 2011 | Planaria | Vmem polarity in intact and regenerating worms | Chemistry & Biology 18(1):77–89 |
| Pietak & Levin 2016 | Xenopus (BETSE validation) | Predicted vs. experimental Vmem comparisons | Frontiers in Bioengineering 4:55 |

**Curation protocol:**

1. Extract Vmem values from published figures (using WebPlotDigitizer or equivalent for quantitative extraction from colormap images).
2. Record the experimental conditions: which channels were blocked/expressed, gap junction state, developmental stage.
3. Map experimental conditions to BETSE-compatible parameters where possible (this mapping is approximate; document assumptions).
4. Store as structured records with source citation, figure reference, and uncertainty estimates.

This is a manual curation step. The builder should create a `data/experimental/` directory with one JSON file per experiment, plus a README documenting the extraction process and assumptions.

## 5. Model Specification

### 5.1 Architecture: Message-Passing Graph Neural Network

The tissue is a graph. Cells are nodes. Gap junctions are edges. The model predicts per-node Vmem from node features (channel densities) and edge features (gap junction conductances).

**Why MPNN**: Message passing is physically motivated. In the real tissue, current flows between cells through gap junctions; the message-passing operation in a GNN is the learned analogue of this physical process. Each message-passing step propagates information across one hop of the graph, analogous to current spreading through one gap junction.

**Framework**: PyTorch + PyTorch Geometric (pyg).

#### 5.1.1 Input Representation

```
Node features x_i ∈ R^{n_channels}:
    Per-cell ion channel / transporter density vector.
    n_channels = 8 (Nav, Kir, K_leak, Ca, Cl, NaKATP, HKATP, VATP).
    Normalized to [0, 1] by dividing by the max of each channel's training range.

Edge features e_ij ∈ R^1:
    Gap junction conductance between cell i and cell j.
    Normalized to [0, 1] by dividing by max training range conductance.

Graph structure:
    edge_index: (2, n_edges) in COO format, undirected (both directions stored).
    Constructed from the gap junction connectivity of each tissue configuration.
```

#### 5.1.2 Network Architecture

```
Encoder:
    MLP(n_channels → 64 → 128), ReLU activations, LayerNorm after each layer.
    Produces initial node embeddings h_i^0 ∈ R^128.

Edge encoder:
    MLP(1 → 32 → 64), ReLU, LayerNorm.
    Produces edge embeddings e_ij ∈ R^64.

Message-passing layers (K = 6 layers):
    For each layer k = 1..K:
        Message:    m_ij^k = MLP_msg([h_i^{k-1} || h_j^{k-1} || e_ij]) → R^128
        Aggregate:  M_i^k  = mean({m_ij^k : j ∈ N(i)})
        Update:     h_i^k  = MLP_upd([h_i^{k-1} || M_i^k]) → R^128
        + Residual connection: h_i^k = h_i^k + h_i^{k-1}
        + LayerNorm after update

    MLP_msg: Linear(128+128+64 → 128 → 128), ReLU
    MLP_upd: Linear(128+128 → 128 → 128), ReLU

Decoder:
    MLP(128 → 64 → 1), outputs predicted Vmem for each node.
    No final activation (Vmem is unbounded in principle, though physically constrained).

Total parameters: ~500K (verify at build time).
```

**Why 6 message-passing layers**: In a hexagonal grid of 50–500 cells, 6 hops covers the diameter of most tissue configurations, allowing the model to integrate information across the full tissue. This is adjustable; start with 6 and ablate.

#### 5.1.3 Baseline Model

Implement a per-cell MLP baseline (no graph structure, no message passing) to quantify how much the graph topology contributes to prediction accuracy.

```
Baseline MLP:
    MLP(n_channels → 128 → 128 → 64 → 1), ReLU, LayerNorm.
    Same input features per cell, but no inter-cell communication.
    Each cell's Vmem is predicted independently from its own channel densities.
```

This baseline should underperform the GNN on configurations with strong gap junction coupling (where inter-cell communication matters) and perform comparably on configurations with zero gap junction conductance (where cells are electrically isolated).

### 5.2 Loss Function

```
Primary loss:
    L = (1/N) Σ_i |V_pred_i - V_true_i|    (MAE, in mV)

    MAE is preferred over MSE because Vmem distributions can have outlier cells
    (e.g., cells at tissue boundaries with different channel densities), and we want
    uniform accuracy across all cells, not accuracy dominated by the largest errors.

Auxiliary loss (optional, for regularization):
    L_physics = (1/N) Σ_i (Σ_j∈N(i) g_ij * (V_pred_i - V_pred_j))^2

    This penalizes predicted Vmem distributions that would produce large net gap junction
    currents, encoding the physical prior that steady-state Vmem should approximately
    satisfy current balance. Weight: λ = 0.01 (tune on validation set).
```

## 6. Training Specification

### 6.1 Data Splits

| Split | Source | Size | Purpose |
|---|---|---|---|
| Train | Baseline BETSE configs | 8,000 | Model training |
| Validation | Baseline BETSE configs | 1,000 | Hyperparameter tuning, early stopping |
| Test (in-distribution) | Baseline BETSE configs | 1,000 | In-distribution accuracy |
| Test (OOD) | Perturbation BETSE configs | 2,000 (500 per type) | Generalization evaluation |
| Test (experimental) | Published Vmem data | ~10–30 data points | Final real-world validation |

Train/val/test splits are by configuration ID (no data leakage: all cells from one simulation go into the same split).

### 6.2 Training Configuration

| Hyperparameter | Value | Notes |
|---|---|---|
| Optimizer | AdamW | |
| Learning rate | 1e-3 | |
| LR schedule | Cosine annealing to 1e-5 over full training | |
| Weight decay | 1e-4 | |
| Batch size | 32 graphs | Each graph is one tissue simulation |
| Max epochs | 200 | |
| Early stopping | Patience 20 epochs on validation MAE | |
| Gradient clipping | Max norm 1.0 | |
| Random seed | 42 (run 3 seeds for variance: 42, 137, 256) | |

### 6.3 Training Infrastructure

- GPU: single NVIDIA GPU (A100, 4090, or whatever is available; the model is small enough to train on consumer hardware).
- Logging: Weights & Biases (wandb) or TensorBoard. Log per-epoch: train MAE, val MAE, val MAE per channel type, learning rate.
- Checkpointing: save best model (by val MAE) and latest model.

## 7. Evaluation Specification

### 7.1 Accuracy Metrics

| Metric | Computed on | Target |
|---|---|---|
| MAE (mV) | Test (in-dist), Test (OOD), Test (experimental) | ≤ 10% of Vmem range |
| R² | Per-cell predicted vs. true Vmem, across test set | > 0.9 (in-dist) |
| Per-channel-type MAE | Group test samples by dominant channel type, report MAE per group | Identify which channel types are hardest to predict |
| Spatial error map | For each test tissue, plot spatial distribution of prediction error | Identify whether errors are uniform or concentrated (e.g., at boundaries) |

**Vmem range**: The "10% of Vmem range" threshold is computed as 0.10 × (max Vmem − min Vmem) across the experimental dataset. For typical non-neural tissue, Vmem ranges from approximately −60 mV to +10 mV, so the threshold is approximately 7 mV MAE.

### 7.2 Generalization Evaluation

For each perturbation type (channel blockade, GJ blockade, exogenous expression, spatial gradient):
- Report MAE, R², and qualitative comparison of predicted vs. true Vmem spatial patterns.
- Compare: does the model predict the *direction* of Vmem change under perturbation correctly, even if the magnitude is off?
- Rank perturbation types by difficulty (MAE).

### 7.3 Speed Benchmark

| Measurement | Protocol |
|---|---|
| BETSE wall-clock time | Run BETSE on 100 test configurations, record wall-clock time per simulation |
| Model inference time | Run the trained model on the same 100 configurations, record wall-clock time per forward pass (including data loading and graph construction) |
| Speedup ratio | BETSE time / model time, reported as median and IQR across configurations |
| Device | Report separately for CPU-only and GPU inference |

### 7.4 Ablations

Run and report the following ablations:

| Ablation | What it tests |
|---|---|
| MLP baseline (no graph) | Contribution of gap junction topology to prediction |
| K = 2, 4, 6, 8 message-passing layers | Optimal propagation depth |
| Without physics auxiliary loss | Contribution of the current-balance regularizer |
| Training set size: 1K, 2K, 4K, 8K | Data efficiency / scaling behavior |
| Without channel density normalization | Sensitivity to input preprocessing |

### 7.5 Deliverable Figures

The evaluation pipeline should produce the following figures (saved as PNGs and as a summary PDF):

1. **Scatter plot**: predicted vs. true Vmem for all cells in the in-distribution test set. One point per cell. Color by tissue config. Include R² and MAE in title.
2. **Perturbation panel**: 2×2 grid, one per perturbation type. Each panel: predicted vs. true Vmem scatter, with MAE annotated.
3. **Spatial error maps**: for 6 representative test tissues (2 baseline, 4 perturbation), show side-by-side: (a) true Vmem heatmap, (b) predicted Vmem heatmap, (c) error heatmap.
4. **Speed bar chart**: BETSE vs. model inference time, with error bars.
5. **Ablation table**: all ablation results in a single table.
6. **Learning curve**: validation MAE vs. epoch.
7. **Experimental validation**: for each curated experimental data point, show predicted vs. measured Vmem with error bars (measurement uncertainty from the literature).

## 10. Build Sequence

This is the order of implementation. Each milestone is independently testable.

### Milestone 1: BETSE Integration (Days 1–3)

**Goal**: Run a single BETSE simulation programmatically and extract Vmem output.

- Install BETSE. Resolve any dependency issues. Document the working installation.
- Write `betse_generator.py`: takes a config dict, generates a BETSE YAML config, runs the simulation via BETSE's CLI or Python API, parses the output, returns the structured result (Section 4.1.2 schema).
- Write `test_betse_generator.py`: run one simulation with a known config, assert output shape and value range.
- Manually verify: does the output Vmem look physically reasonable (−120 to +60 mV range, convergence to steady state)?

**Exit criterion**: `python -m pytest tests/test_betse_generator.py` passes. One BETSE simulation completes end-to-end and produces valid Vmem output.

### Milestone 2: Data Generation Pipeline (Days 3–5)

**Goal**: Generate the full synthetic training dataset.

- Write `config_sampler.py`: LHS sampling over the parameter space (Section 4.1.1). Each sample is a complete config dict.
- Write `validation.py`: post-generation quality checks (Section 4.1.4).
- Write `generate_data.py` script: orchestrates sampling, parallel BETSE execution, validation, and persistence.
- Generate a small pilot dataset (N=100) first. Inspect outputs. Fix any issues.
- Generate the full dataset (N=10,000 baseline + 2,000 perturbation). Log failures and generation time.

**Exit criterion**: `data/synthetic/` contains ≥9,500 valid baseline simulations and ≥1,800 valid perturbation simulations. Manifest CSV is complete. Validation checks pass.

**Note**: This is the longest milestone by wall-clock time (BETSE is slow). Estimate: if each simulation takes ~60s on average, 12,000 simulations across 8 cores ≈ 25 hours. Start this early and let it run.

### Milestone 3: Dataset and DataLoader (Days 5–6)

**Goal**: PyTorch Geometric dataset that loads synthetic data into graph format.

- Write `dataset.py`: subclass `InMemoryDataset`. Each sample becomes a `torch_geometric.data.Data` object with:
  - `x`: node features (n_cells, n_channels), normalized.
  - `edge_index`: (2, n_edges), COO format.
  - `edge_attr`: (n_edges, 1), normalized GJ conductance.
  - `y`: (n_cells,), target Vmem in mV.
- Implement train/val/test/ood splits per Section 6.1.
- Write `test_dataset.py`: assert tensor shapes, dtype, value ranges, split sizes.

**Exit criterion**: `DataLoader(dataset, batch_size=32)` iterates without error. Tensor shapes are correct. Splits don't leak.

### Milestone 4: Model Implementation (Days 6–8)

**Goal**: MPNN and baseline MLP forward passes produce correct output shapes.

- Write `mpnn.py`: architecture per Section 5.1.2.
- Write `baseline.py`: per-cell MLP per Section 5.1.3.
- Write `losses.py`: MAE loss + optional physics auxiliary loss per Section 5.2.
- Write `test_model.py`: forward pass on a single batch, assert output shape is (total_nodes_in_batch,).

**Exit criterion**: `python -m pytest tests/test_model.py` passes for both MPNN and baseline.

### Milestone 5: Training Loop (Days 8–10)

**Goal**: Model trains, loss decreases, checkpoints save.

- Write `trainer.py`: training loop with early stopping, LR scheduling, gradient clipping, wandb/tensorboard logging, checkpoint saving.
- Write `config.py`: pydantic dataclass for all hyperparameters, loadable from YAML.
- Write `train.py` script.
- Run a short training (10 epochs) on a subset (1,000 samples) to verify the loop works end-to-end.
- Run full training (200 epochs, 8,000 samples) with 3 random seeds.

**Exit criterion**: Training completes. Validation MAE decreases over epochs. Best checkpoint is saved. Logs are viewable.

### Milestone 6: Evaluation Pipeline (Days 10–13)

**Goal**: All metrics computed, all figures generated.

- Write `metrics.py`, `generalization.py`, `speed_benchmark.py`, `figures.py`.
- Write `evaluate.py` script: loads best checkpoint, runs all evaluations, saves metrics and figures.
- Write `run_ablations.py`: runs ablation experiments per Section 7.4.
- Run full evaluation. Generate all deliverable figures (Section 7.5).

**Exit criterion**: All 7 deliverable figures are generated. Metrics table is complete. Speed benchmark is run. Success criteria (Section 2) are evaluated and reported.

### Milestone 7: Experimental Validation (Days 13–15)

**Goal**: Model predictions compared to published experimental Vmem.

- Curate experimental data (Section 4.2). This is partly manual.

## 11. Technical Decisions and Constraints

### 11.1 Why Steady-State First

BETSE simulates temporal dynamics, but the primary prediction target for Phase 1 is steady-state Vmem (the equilibrium the tissue converges to). Reasons:

1. Steady-state is the more constrained problem: there is one correct answer per configuration, not a trajectory. This makes evaluation unambiguous.
2. Experimental Vmem data (voltage reporter dyes) captures steady-state, not dynamics. Dye equilibration takes minutes.
3. The Phase 2 transfer to neural tissue will require temporal prediction (spikes are dynamic). But Phase 1's goal is to establish that the learned prediction approach works at all, not to solve the hardest version of the problem first.

The Vmem time series data captured for 1,000 simulations (Section 4.1.2, step 2) is stored for potential future extension but is not used in v1 evaluation.

### 11.2 BETSE as Ground Truth vs. Experimental Data

BETSE is the synthetic ground truth for training and in-distribution testing. Experimental data is the real-world ground truth for final validation. These are different:

- BETSE is validated to within ~10% of experimental measurements (Pietak & Levin 2016). The model trained on BETSE data will inherit BETSE's systematic errors.
- If the model achieves ≤10% MAE against BETSE but >10% against experimental data, the conclusion is: the model learned BETSE's behavior (success for the learned surrogate goal) but didn't exceed BETSE's accuracy (not a failure, but a ceiling).
- If the model achieves ≤10% MAE against experimental data, the conclusion is stronger: the model has learned bioelectric dynamics at least as well as the physics simulator.

### 11.3 Scope Boundaries

Phase 1 does NOT include:
- Temporal dynamics prediction (steady-state only).
- Neural tissue of any kind (non-neural only).
- Integration with transcriptomic data (that is Phase 2).
- Any connectomics or Neuropixels data (Phases 3+).
- Inverse prediction (predicting channel densities from desired Vmem; future direction).
- Deployment, API, or user-facing interface (this is a research artifact).

### 11.4 BETSE Failure Modes

BETSE may fail on certain parameter combinations (numerical instability, non-convergence). Expected failure rate: 5–15% of sampled configs. Handle by:
- Wrapping each simulation in a try/except with a timeout (5x median simulation time).
- Logging failures with their configs for post-hoc analysis.
- Oversample by 15% to compensate (i.e., sample 11,500 configs to get 10,000 valid baseline results).

## 12. What This Enables

If Phase 1 succeeds:

1. **Phase 2 pretraining**: The MPNN weights from Phase 1 encode learned representations of how ion channel configurations produce bioelectric states. These transfer as pretrained weights for Phase 2, where the input shifts from BETSE channel densities to transcriptomic expression levels and the prediction target shifts from tissue Vmem to single-cell electrophysiological features.

2. **Publication**: A published proof-of-concept demonstrating that learned bioelectric prediction generalizes beyond the simulator it was pretrained on. Target venue: PLoS Computational Biology, Bioinformatics, or a relevant NeurIPS workshop.

3. **BETSE surrogate**: A fast surrogate for BETSE that runs orders of magnitude faster, enabling large-scale parameter sweeps and experimental design that are currently computationally prohibitive.

If Phase 1 fails (model cannot generalize to perturbation conditions):

1. Characterize the failure: which perturbation types fail, and why? Is it an architecture problem (not enough message-passing depth), a data problem (not enough training variety), or a fundamental problem (the prediction is not learnable from the specified inputs)?
2. Iterate: try deeper models, more training data, additional input features (e.g., ion concentrations, not just channel densities), or physics-informed neural network approaches (PINNs).
3. If generalization fails completely, the Phase 1 conclusion is: learned surrogates for BETSE work in-distribution but do not generalize, which means Phase 2 cannot rely on pretrained representations from non-neural tissue and must learn transcript-to-electrophysiology from scratch with ~100 data points, which is harder but not impossible.
